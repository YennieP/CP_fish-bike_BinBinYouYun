# 豆瓣小组长帖备份

把一个豆瓣小组帖子的全部回复（含 GIF 动图、发帖人头像）备份到本地，生成可离线阅读的 HTML；
另外可以生成一份体积小、隐去用户 ID 的**分享版离线包**，发给楼里的朋友，解压后双击就能看。

> 本工具只用于个人留存和小范围分享。备份内容的版权属于原发帖人，请不要公开转载。

## 原帖指路

- 原帖：[《天后》真的很微妙……（离婚快乐）](https://www.douban.com/group/topic/500345559/)（2026-09-20 开楼）
- 楼层导航：[建设一个天后微妙/鱼车CP楼蹬车导航（楼层目录）](https://www.douban.com/group/topic/503844576/)（楼友整理的精华索引；其中的“第 N 页”是豆瓣手机端页码）

原帖需要登录豆瓣才能查看。

## 准备

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Cookie：浏览器登录豆瓣后，从开发者工具 Network 里复制请求头 `Cookie` 的值，存到
`~/.config/douban-backup/cookie.txt`（`chmod 600`），也可以用环境变量 `DOUBAN_COOKIE`。
Cookie 不会被打印，也不在项目目录里，不会进 Git。

## 使用

每一步都可以随时中断，重新运行同一条命令就会从断点继续。

```bash
.venv/bin/python backup.py text --max-pages 40   # 1. 抓文字（本次最多 40 页）
.venv/bin/python backup.py images                # 2. 下载图片（原始文件，GIF 原样保存）
.venv/bin/python backup.py avatars               # 3. 下载发帖人头像
.venv/bin/python backup.py render                # 4. 生成存档版 HTML
.venv/bin/python backup.py share                 # 5. 生成分享版并打包（完整包 + 更新包）
.venv/bin/python backup.py epub --full           # 6. 手机版：整楼一本 EPUB
.venv/bin/python backup.py epub --per-book 2500  #    手机版：每 2500 楼一册（--volumes 5 只生成第 5 册）
.venv/bin/python backup.py bundle                # 7. 整理上传网盘用的文件夹
.venv/bin/python backup.py status                # 查看进度（一行）
.venv/bin/python backup.py progress              # 实时进度条（只读，不发请求）
```

- 存档版：打开 `data/<帖子ID>/html/index.html`；地址后加 `#f123` 定位到第 123 楼。
- 其他帖子：所有命令都可以加 `--topic <帖子ID>`。
- `--start 1200` 可以跳过断点，从指定的 `start` 值开始抓。

## 楼增高后怎么更新

### 日常更新：一条命令

```bash
.venv/bin/python backup.py update
```

按顺序自动完成下面 7 步，最后列出这次要告诉朋友下载哪些文件：

1. `text`：从断点翻到末页，补新回复（不用再估 `--max-pages`）
2. `images`：只下新图片
3. `avatars`：只下新发帖人的头像
4. `render`：存档版
5. `share`：分享版完整包 + 更新包
6. `epub`：手机版全本，以及需要重新生成的分册，并重新打分册 zip
   （按上个版本的楼数算：平时只有最后一册；跨过 2500 楼的整数倍时，上一册补满、再新开一册）
7. `bundle`：整理上传文件夹

- 和上个版本相比没有新回复时，在第 4 步之前停下，不生成空版本。
- 被风控拦下时立刻停止，已生成的成品不受影响；处理好之后重新运行 `update` 即可。
- `update --refresh`：第 1 步改为全量复查（见下文），分册全部重新生成。
- `update --offline`：不联网，只用已有数据重新生成成品。
- 也可以照旧一步步运行上面这些命令，效果一样。

- 抓到末页后，断点会停在末页。`text` 每次先重抓这一页拿到新回复，再顺着“后页”往后翻。
- `text` 默认一次只抓 5 页，新增页数多时加大 `--max-pages`，或者多跑几次，直到看到“已到最后一页”。
- 已备份的楼层号和发帖人序号都不会变，新内容只往后追加，`#f123` 这样的定位一直有效。
- 日常更新**不会**重新看旧页面：旧楼层的点赞数、主楼修改、删帖都要靠下面的全量复查。

### 全量复查：更新旧楼层

```bash
.venv/bin/python backup.py text --refresh
```

从第 1 页重新翻到末页（约 125 页、10 分钟，限速和平时一样），然后：

- 更新每条旧回复的点赞数、“楼主赞过”。
- 主楼有修改时更新主楼，旧版本存进 `topic_history/`。
- 这一轮没翻到的回复，再按它应在的位置核对一遍那一页，确认不在了才标记为**原帖已删除**。
  备份里保留原文，楼层号不变；以后如果又出现了，标记会自动去掉。
- 没翻到的超过 5% 时，多半是页面异常，这次不做删除标记，名单存在 `refresh-<编号>-missing.json`。
- 可以随时中断，再运行同一条命令会接着查。复查顺带补上新回复，之后照常跑 2 → 5。

平时不需要，隔一两个月，或者发完整包之前跑一次即可。

### 发给朋友

`share` 每次都会生成完整包，并和**上一次运行 `share`** 的结果对比，另外生成一个只含变化文件的更新包
（`douban-<帖子ID>-update-<上个版本>-to-<本次版本>.zip`）。

- 更新包里带着 `douban-<帖子ID>/` 这一层文件夹，朋友要把它解压到这个文件夹**所在的位置**，选择覆盖。
- 更新包是一个接一个的：每次生成的都要发，中间漏了一个，后面的就补不全。
- 朋友漏装了、或者不确定装到哪一版了，直接重新下载完整包最省事。

### 整理上传文件夹

```bash
.venv/bin/python backup.py bundle
```

把要上传网盘的文件整理到 `dist/upload/<帖子标题>-离线备份-<版本>/`，整个文件夹拖进网盘客户端即可：

```
00-先看我-下载说明.txt    给朋友的说明：电脑 / 手机各下哪个、怎么打开
电脑版/                   完整包 zip；有更新包时一并放入
手机版-全本/              全本 EPUB
手机版-分N册/             分册 EPUB
手机版-分N册-打包/         全部分册打成的一个 zip，方便一次下载
```

- 文件是硬链接，不额外占用磁盘；删掉这个文件夹不影响 `dist/` 里的原文件。
- 只保留最新一版的上传文件夹，更早的会自动删掉（它们只是硬链接，留着会让被替换掉的旧版全本、旧分册继续占用磁盘；完整包和更新包的 zip 原件仍在 `dist/` 里）。
- 整理前会检查：分册要连续并收到最后一楼；完整包、全本和最后一册不能比最新数据旧；分册 zip 里正好是当前这些分册。不满足时会停下并提示先重新生成哪些文件，
  避免把旧文件传上去。所以更新时要先跑完 `share` 和 `epub`，再运行 `bundle`。
- 前面几册不随新回复变化，所以不检查它们。跑过全量复查（`text --refresh`）后，旧楼层的点赞、删帖标记会变，
  要用 `epub --per-book 2500` 把所有分册重新生成一遍。
- 版本号跟分享版一致（最近一次 `share` 的时间）。

### Cookie 过期

隔很久再运行时，程序可能停下并提示“已暂停”（退出码 2）。这时用浏览器登录豆瓣确认账号正常，
重新复制 Cookie 存到 `~/.config/douban-backup/cookie.txt`，再运行同一条命令就会从断点继续。

## 安全约束

- 单线程；翻页间隔随机 3～6 秒，图片和头像间隔 1～2.5 秒。
- 遇到非 200、重定向（登录页 / sec.douban.com）、页面里没有帖子内容、图片全部 403 时，
  **立刻停止**（退出码 2），已抓内容都已保存，不做重试。
- 网络错误（断网、超时）不是风控信号：等 15 秒、45 秒各重试一次，仍失败再退出（退出码 3）。

## 三个版本的区别

`dist/` 里的文件夹名都带版本时间（`YYYYMMDD-HHMM`，即最近一次运行 `share` 的时间），手机版沿用同一个版本号，
同一次更新的电脑版和手机版对得上。下次生成时，旧文件夹会直接改名成新版本接着用，所以每类只保留最新的一份。
分享包压缩包里的文件夹固定叫 `douban-<帖子ID>/`，不带版本，朋友解压更新包时才能覆盖到同一个文件夹里。

| | 存档版 `data/<帖子ID>/html/` | 分享版 `dist/douban-<帖子ID>-<版本>/` | 手机版 `dist/epub-<版本>/` |
|---|---|---|---|
| 打开方式 | 电脑浏览器 | 电脑浏览器（解压后双击） | 下载到手机，用 Apple Books、微信读书等阅读器打开 |
| 动图 | 原始 GIF | 转成 MP4，静音循环播放，滚动到时才加载 | 缩小的 GIF（宽 400px、12 帧/秒、128 色） |
| 图片 | 原始文件 | 长边缩到 1280px，JPEG 质量 80 | 同分享版 |
| 楼层定位 | `#f123`、跳转框 | `#f123`、跳转框 | 两层目录：每 500 楼一组，每 50 楼一章 |
| 发帖人 | 昵称 · 用户 ID 后 4 位 | 昵称 · 本帖内序号（如“momo·84号”），没有用户 ID 和主页链接 | 同分享版 |
| 默认昵称“豆友<ID>” | 原样 | 显示为“豆友·N号” | 同分享版 |
| 头像、IP 属地、时间、点赞、引用 | 有 | 有 | 有；引用别册的楼层显示为“#1234（第 3 册）” |

手机版有两种，可以都发，让大家按需下载。生成的文件在 `dist/epub-<版本>/` 下分开放：

```
全本/douban-<帖子ID>-全本.epub
分册-每2500楼/douban-<帖子ID>-01（1-2500楼）.epub ……
douban-<帖子ID>-手机版-分册-每2500楼.zip      所有分册打成一个包，方便一次下载
```


- **全本**（`--full`，约 1.1 GB）：整楼一个文件，引用都能点过去。翻页流畅，跨章节跳转会卡一下。
- **5 册**（`--per-book 2500`，每册 130～340 MB）：文件小，跳转更快；引用到别册的楼层只显示楼层号。
  按楼数固定分册，楼增高后只有最后一册会变，满 2500 楼再新开一册，所以更新时只需要重新发最后一册（和全本）。

序号按每位发帖人在楼里第一次出现的顺序编号，更新后老用户的编号不变。

## 数据目录 `data/<帖子ID>/`

| 文件 | 内容 |
|---|---|
| `replies.jsonl` | 每行一条回复（文字阶段的数据和断点），按回复 ID 去重 |
| `updates.jsonl` | 全量复查记下的变化（点赞数、楼主赞过、已删除），读取时叠加到 `replies.jsonl` 上 |
| `topic.json`、`topic_history/` | 主楼；主楼被修改过时，旧版本存在 `topic_history/` |
| `state.json` | 翻页断点 `cursor`、已抓页、总页数 |
| `pages/start_XXXXXX.html` | 原始页面缓存；改解析器后可以直接重新解析，不用再请求。全量复查的页面另存在 `pages/refresh-<编号>/`，不覆盖原始页面 |
| `images/`、`images.jsonl` | 图片原文件和下载记录。GIF 存为 `.gif`；少数动图表情只有视频版，另存 `.mp4` |
| `avatars/`、`avatars.json` | 头像（按内容哈希命名，文件名里没有用户 ID）和下载记录 |
| `share_media/` | 分享版压缩后的素材缓存，只转换新增的 |
| `epub_media/` | 手机版缩小后的 GIF 和封面，只转换新增的 |
| `releases/` | 每次发布的文件清单，用来生成更新包 |

## 图片规则

- 一律下载 `raw` 尺寸（原文件）；`large` / `s` 尺寸会把 GIF 转成静态首帧。
- 候选地址顺序：页面里带签名的原图地址 → 无签名的 `img3.doubanio.com/.../raw/...` → `large`。
- 按文件头判断格式（豆瓣把 GIF 也标成 `.jpg`）；按图片编号去重。

## 楼层号

豆瓣网页不显示楼层号。这里按回复 ID 升序编号（主楼是第 0 楼），删帖不会让已备份的楼层号变化，
但可能和豆瓣 App 里的页码对不上。每条记录也保存了抓取时所在的 `page_start` 和 `page_index`。
