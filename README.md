# 豆瓣小组长帖备份

把一个豆瓣小组帖子的全部回复（含 GIF 动图、发帖人头像）备份到自己电脑上，再做成三种可以离线看的版本：

| 版本 | 给谁看 | 怎么看 |
|---|---|---|
| **存档版** | 自己留存（原图、原 GIF） | 电脑浏览器打开 |
| **电脑版**（分享版） | 发给楼里的朋友，体积小，隐去用户 ID | 解压后双击 `点我打开.html` |
| **手机版** | 发给楼里的朋友 | EPUB 电子书，用 Apple Books 等阅读器打开 |

楼还在盖的话，以后只要运行一条命令 `update`，就能补上新回复、重新生成三个版本，并整理好要上传网盘的文件夹。

> 本工具只用于个人留存和小范围分享。备份内容的版权属于原发帖人，请不要公开转载。

## 原帖指路

- 原帖：[《天后》真的很微妙……（离婚快乐）](https://www.douban.com/group/topic/500345559/)（2026-09-20 开楼）
- 楼层导航：[建设一个天后微妙/鱼车CP楼蹬车导航（楼层目录）](https://www.douban.com/group/topic/503844576/)（楼友整理的精华索引；其中的“第 N 页”是豆瓣手机端页码）

原帖需要登录豆瓣才能查看。

## 一、第一次使用

### 1. 安装

需要 Python 3.9 或更高版本。在项目文件夹里运行：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### 2. 放好豆瓣 Cookie

帖子要登录才能看，所以程序需要你浏览器里的登录 Cookie。以 Chrome 为例：

1. 登录豆瓣，打开原帖页面。
2. 按 `F12` 打开开发者工具，切到 **Network（网络）**，刷新页面。
3. 点列表里第一条请求（名字是 `500345559/`），在右边 **Request Headers（请求标头）** 里找到 `Cookie`，复制它的值（很长的一串）。
4. 在终端里运行下面三行，把剪贴板里的 Cookie 存成文件（Mac）：

```bash
mkdir -p ~/.config/douban-backup
pbpaste > ~/.config/douban-backup/cookie.txt
chmod 600 ~/.config/douban-backup/cookie.txt
```

- Cookie 存在你的用户目录里，不在项目文件夹里，不会进 Git，程序也不会把它打印出来。
- 也可以不存文件，改用环境变量 `DOUBAN_COOKIE`。
- **不要把 Cookie 发给任何人**，它等于你的豆瓣登录状态。

### 3. 第一次备份

```bash
.venv/bin/python backup.py update
```

第一次会从第 1 页抓到最后一页，再下载全部图片和头像，时间比较长（这个楼约 125 页、1600 张图，翻页约 10 分钟，图片约 3 小时）。

- **随时可以中断**（`Ctrl+C`、断网、关机都行）。重新运行同一条命令，会从断点接着来，已经下好的不会重下。
- 想看进度，另开一个终端运行 `.venv/bin/python backup.py progress`，会显示进度条（只读本地文件，不访问豆瓣）。

跑完后，三个版本都在这里：

- 存档版：`data/500345559/html/index.html`，用浏览器打开
- 电脑版、手机版：`dist/` 里（见下面“[三、文件都在哪](#三文件都在哪)”）
- 要上传网盘的文件夹：`dist/upload/` 里

## 二、楼增高后怎么更新

### 日常更新：一条命令

```bash
.venv/bin/python backup.py update
```

它会按顺序做 7 件事，每一步都只处理新增的部分：

| 步骤 | 做什么 |
|---|---|
| 1. 补新回复 | 从上次停下的最后一页开始，翻到新的最后一页 |
| 2. 下载新图片 | 只下还没下过的 |
| 3. 下载新头像 | 只下新出现的发帖人的 |
| 4. 存档版 | 重新生成 |
| 5. 电脑版 | 生成完整包，以及只含变化文件的**更新包** |
| 6. 手机版 | 重新生成全本；分册只重新生成有变化的那一两册 |
| 7. 上传文件夹 | 把上面这些整理到一个文件夹里，附上给朋友的下载说明 |

**例子**：2026-10-28 这次更新，楼从 12458 楼长到 12539 楼，运行结束时会打印：

```
✅ 新版本 20261028-1405：12458 → 12539 楼
上传文件夹：dist/upload/《天后》真的很微妙……（离婚快乐）-离线备份-20261028-1405
这次要告诉朋友的：
  · 电脑版：已有旧版本的，只下载更新包 douban-500345559-update-20261028-1155-to-20261028-1405.zip；新朋友下载完整包
  · 手机版全本：重新下载整本
  · 手机版分册：只需重新下载 douban-500345559-05（10001-12500楼）.epub、douban-500345559-06（12501-12539楼）.epub
```

这次正好跨过了 12500 楼，所以第 5 册补满成“10001-12500楼”，又新开了第 6 册。平时只会有最后一册变化。

几种情况：

- **没有新回复**：在第 4 步之前停下，什么都不生成（避免多出一个空版本）。
- **被豆瓣拦下**（提示“⛔ 已暂停”）：立刻停止，之前生成的东西都不受影响。处理方法见“[常见问题](#六常见问题)”。
- **中途断了**：重新运行 `update` 即可。

### 全量复查：更新旧楼层（偶尔做）

日常更新**只看最后几页**，所以旧楼层的变化不会被发现，例如：第 100 楼的点赞从 5 涨到 50、楼主后来给第 200 楼点了赞、第 300 楼被作者删了。要更新这些，运行：

```bash
.venv/bin/python backup.py update --refresh
```

它会从第 1 页重新翻到最后一页（约 125 页、10 分钟），然后：

- 更新每条旧回复的点赞数和“楼主赞过”；主楼被改过的话，更新主楼（旧版本存进 `data/500345559/topic_history/`）。
- 找不到的回复会再核对一遍，确认真的不在了，才标上 **“原帖已删除”**。原文会保留，楼层号不变。以后如果它又出现了，标记会自动去掉。
- 一次有超过 5% 的回复找不到时，多半是页面出了问题而不是真被删了，这次不做删除标记。
- 因为旧楼层变了，手机版的**所有分册**都会重新生成，朋友需要重新下载全部分册。

平时不需要，隔一两个月跑一次就够了。

### 不联网，用已有数据接着生成

比如上次 `update` 已经补完了新回复，但在生成手机版时被打断了，可以不再访问豆瓣，直接接着生成：

```bash
.venv/bin/python backup.py update --offline
```

和上个版本相比没有新回复时，它同样会直接停下，不生成新版本。

## 三、文件都在哪

### `dist/`：要发给朋友的东西

文件夹和压缩包名字里的 `20261028-1405` 是**版本号**，就是生成电脑版的时间（2026 年 10 月 28 日 14:05）。同一次更新的电脑版、手机版、上传文件夹都用同一个版本号。

```
dist/
├── douban-500345559-20261028-1405/                             电脑版文件夹（解压后就是这个样子）
├── douban-500345559-full-20261028-1405.zip                     电脑版完整包（246 MB）
├── douban-500345559-update-20261028-1155-to-20261028-1405.zip  电脑版更新包（2 MB，只含 1155 → 1405 的变化）
├── epub-20261028-1405/                                         手机版
│   ├── 全本/douban-500345559-全本.epub                          整楼一本（1.0 GB）
│   ├── 分册-每2500楼/douban-500345559-01（1-2500楼）.epub …… 06   每 2500 楼一册
│   └── douban-500345559-手机版-分册-每2500楼.zip                 全部分册打成一个包
└── upload/
    └── 《天后》真的很微妙……（离婚快乐）-离线备份-20261028-1405/      整个拖进网盘即可（见下一节）
```

电脑版文件夹里只有三样东西，朋友一打开就知道从哪里开始：

```
douban-500345559/
├── 点我打开.html     入口（目录页）
├── 使用说明.txt      怎么打开、标记的意思、怎么更新
└── 内容/            26 个分卷网页和全部图片、视频、头像
```

**`dist/` 不会越积越多**：每次更新后，每样东西都只留最新的一份。

- 文件夹：旧的直接改名成新版本号接着用（比如 `epub-20261028-1155/` 变成 `epub-20261028-1405/`）。
- 压缩包：只留最新的完整包，和“上一版 → 这一版”的更新包，更早的自动删掉。
- 上传文件夹：只留最新一版。

### `data/500345559/`：抓下来的原始数据（只给自己用）

| 文件 | 内容 |
|---|---|
| `html/` | 存档版 |
| `replies.jsonl` | 所有回复，每行一条 |
| `updates.jsonl` | 全量复查记下的变化（点赞数、楼主赞过、已删除） |
| `topic.json`、`topic_history/` | 主楼；被修改过时旧版本存在 `topic_history/` |
| `state.json` | 翻页断点（下次从哪一页开始） |
| `pages/` | 抓到的原始网页，改程序后可以直接重新解析，不用再访问豆瓣 |
| `images/`、`images.jsonl` | 图片原文件和下载记录 |
| `avatars/`、`avatars.json` | 头像（文件名是内容哈希，不含用户 ID） |
| `share_media/`、`epub_media/` | 电脑版、手机版压缩过的图片缓存，只处理新增的 |
| `releases/` | 每个版本的文件清单，用来算出更新包里该放哪些文件 |

`data/` 和 `dist/` 都不会进 Git。

## 四、上传网盘、发给朋友

### 上传

每次 `update` 结束后，把 `dist/upload/` 里的那个文件夹**整个拖进网盘客户端**。网盘上只需保留最新一版：先删掉旧版本的文件夹，再上传新的。

上传文件夹里是这样的：

```
00-先看我-下载说明.txt     给朋友看的：电脑、手机各下哪个、怎么打开、怎么更新
电脑版/                    完整包 +（有的话）更新包
手机版-全本/               全本 EPUB
手机版-分6册/              6 个分册 EPUB，可以单独下载
手机版-分6册-打包/          6 个分册打成的一个 zip，方便一次下完
```

- 文件夹里的文件是硬链接，不额外占用你的磁盘。
- 整理之前会自动检查，避免把旧文件传上去（比如手机版还没重新生成）。不通过时会提示先重新生成哪一样。
- 下载说明里写明了：手机上要先下载再打开，网盘里直接预览多半显示不全。

### 朋友该下载什么（例子）

以 1405 这一版为例：

| 朋友 | 情况 | 下载什么 |
|---|---|---|
| 小 A | Windows，装过上一版（1155） | 只下 2 MB 的**更新包**，解压到原文件夹的上一层，选“替换” |
| 小 B | Mac，装过上一版 | 重新下载**完整包**（Mac 双击解压不会覆盖旧文件，见下方说明） |
| 小 C | 第一次下载，或者漏了好几版 | 下载**完整包** |
| 小 D | 手机看全本 | 重新下载**全本**（1.0 GB） |
| 小 E | 手机看分册 | 只重新下载**第 5、6 册**；第 1–4 册不用动 |

### 电脑版更新包怎么用

更新包只含有变化的文件（这次是 26 卷网页和 5 张新图，共 2 MB），解压后覆盖到旧版本上，就和新的完整包一模一样。

- **压缩包里自带一层 `douban-500345559/` 文件夹**，所以要解压到这个文件夹的**上一层**，不是解压到它里面。
  例子：朋友的电脑版放在 `下载/douban-500345559/`，那么更新包要解压到 `下载/`。
- **Windows**：右键更新包 →“全部解压缩”，目标选上一层，问是否替换时选“替换”。（未实测）
- **Mac**：双击解压**不会覆盖**，只会在旁边多出一个 `douban-500345559 2`，等于没更新（已实测）。
  Mac 用户最省事的办法是重新下载完整包；会用终端的话，在上一层运行 `ditto -x -k 更新包.zip .` 也行（已实测）。
- **有文件被删除或改名时，不生成更新包**：更新包只能新增和覆盖文件，删不掉旧文件。比如调整了文件夹结构，
  朋友装了更新包后会留下一堆旧文件，所以这一次 `share` 会跳过更新包，结尾的清单也会提示“下载完整包”。
- **只能从上一版升级**：1155 → 1405 的更新包，只对装着 1155 的人有用。漏掉中间版本的人，直接下载完整包。
  因为 `dist/` 只保留最新的更新包，网盘上也一样。

### 手机版怎么更新

EPUB 没法“打补丁”，只能用新文件替换旧文件：

- **全本**：每次更新都要整本重新下载（约 1 GB）。
- **分册**：按楼数固定分册，前面的册子不会再变，只需重新下载最后一两册。

所以经常追更的朋友，建议用分册或电脑版。

## 五、三个版本的区别

| | 存档版 | 电脑版 | 手机版 |
|---|---|---|---|
| 位置 | `data/500345559/html/` | `dist/douban-500345559-<版本>/` | `dist/epub-<版本>/` |
| 打开方式 | 电脑浏览器（`index.html`） | 电脑浏览器（解压后双击 `点我打开.html`） | 下载到手机，用 Apple Books 等阅读器打开 |
| 动图 | 原始 GIF | 转成视频，静音循环播放，滚动到时才加载 | 缩小的 GIF（宽 400px） |
| 图片 | 原图 | 长边缩到 1280px | 同电脑版 |
| 跳到某一楼 | 地址后加 `#f123`，或用页面顶部的跳转框 | 同存档版 | 目录：每 500 楼一组、每 50 楼一章 |
| 发帖人 | 昵称 + 用户 ID 后 4 位 | 昵称 + 本帖内序号（如“momo·84号”），没有用户 ID 和主页链接 | 同电脑版 |
| 头像、IP 属地、时间、点赞、引用 | 有 | 有 | 有；引用到别册的楼层显示为“#1234（第 3 册）” |

- **“·N号”**是按每个人第一次在楼里出现的顺序编的号，用来区分同名的人（楼里有很多“momo”）。以后更新时，老用户的号码不变。
- 没设昵称的人，豆瓣显示为“豆友12345678”这样带 ID 的名字；电脑版和手机版里改成“豆友·N号”。
- **手机版两种都可以发**：全本是一个文件，引用都能点过去，但跨章节跳转会卡一下；分册文件小、跳转快，适合追更。

## 六、常见问题

**运行时提示“⛔ 已暂停”，怎么办？**
说明豆瓣返回了登录页、验证码或 403。程序会立刻停下，已经抓到的都保存好了。
用浏览器打开豆瓣，看看是否要求验证或重新登录；如果 Cookie 过期了，按“[放好豆瓣 Cookie](#2-放好豆瓣-cookie)”重新存一次。隔一段时间再运行同一条命令，会从断点继续。

**提示“🌐 网络错误”？**
断网或超时。程序已经自动等 15 秒、45 秒各重试过一次。网络恢复后重新运行同一条命令即可。

**楼层号为什么和豆瓣 App 对不上？**
豆瓣网页不显示楼层号。这里按回复发出的先后（回复 ID）编号，主楼是第 0 楼。有人删帖后，豆瓣 App 的页码会前移，但这里已经备份的楼层号不会变，所以两边可能对不上。

**只想重新做某一样，不想全跑？**
`update` 的每一步都可以单独运行：

| 命令 | 作用 |
|---|---|
| `backup.py text --max-pages 30` | 补新回复（一次最多 30 页；`--refresh` 为全量复查） |
| `backup.py images` | 下载新图片 |
| `backup.py avatars` | 下载新头像 |
| `backup.py render` | 生成存档版 |
| `backup.py share` | 生成电脑版完整包和更新包 |
| `backup.py epub --full` | 生成手机版全本 |
| `backup.py epub --per-book 2500` | 生成手机版分册（加 `--volumes 5 6` 只生成第 5、6 册） |
| `backup.py bundle` | 整理上传文件夹 |
| `backup.py status` | 一行显示进度 |
| `backup.py progress` | 实时进度条 |

命令前面都要加 `.venv/bin/python `，例如 `.venv/bin/python backup.py status`。
**注意**：单独运行 `share` 也会产生一个新版本。只是想试试效果的话，用 `share --no-zip`，它不会记录版本、不打包。

**想备份别的帖子？**
所有命令都可以加 `--topic <帖子ID>`，例如 `.venv/bin/python backup.py --topic 503844576 update`。

## 七、对豆瓣的访问方式（安全约束）

- 单线程，不并发。翻页之间随机等 3～6 秒，图片和头像之间等 1～2.5 秒。
- 遇到非 200、跳转到登录页或 `sec.douban.com`、页面里没有帖子内容、图片全部 403 时，**立刻停止**（退出码 2），不做重试。
- 断网、超时不算风控：等 15 秒、45 秒各重试一次，还不行再退出（退出码 3）。
- 使用正常的浏览器 User-Agent，不做任何绕过验证码的事。

### 技术细节

- **图片**：一律下载原图（`raw` 尺寸），因为小尺寸会把 GIF 变成静态图。豆瓣把 GIF 也标成 `.jpg`，所以按文件内容判断真实格式。
- **楼层号**：按回复 ID 从小到大编号；每条记录也存了抓取时所在的页（`page_start`）和页内位置（`page_index`）。
- **用户 ID**：电脑版和手机版里不出现任何用户 ID、主页链接或豆瓣头像地址；头像文件按内容哈希命名。
